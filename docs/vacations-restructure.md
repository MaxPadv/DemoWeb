# Фича: «Отпуска» → два сервиса (Оформить / Запланировать)

Статус: **реализовано** (as-built, после ревью).

## Что сделано

- Страница «Отпуска» — **экран выбора сервиса**: сетка из **двух крупных карточек-кнопок**
  (как `svc-card` на главной, классы `vc-service-card`/`vc-badge`):
  - **«Запланировать отпуск»** — «Открыть →» → текущая реализация целиком (форма «Новая заявка»
    без выбора типа + календарь пересечений + список «Заявки» с решениями HR).
  - **«Оформить отпуск»** — «Открыть →» → заглушка («Функционал в разработке. Отдельный сервис.»).
- Из выбранного сервиса — кнопка «← К выбору сервиса» (как back-btn на главной).
- Из формы планирования **убран селектор «Тип»** — только **Ежегодный** (`type:'annual'`).
  Бэкенд не менялся.
- Старый таб-бар `vc-tabs` удалён.

## Зачем

Вкладка «Отпуска» сейчас — один экран (форма + календарь + заявки). По бизнес-логике это
**два независимых сервиса**: «Оформить отпуск» и «Запланировать отпуск». Разграничиваем их.

## Решение (по уточнению пользователя)

1. Страница «Отпуска» (из вкладки/кнопки) → на ней **два сервиса**:
   - **«Оформить отпуск»** — пока **заглушка** (карточка «Функционал в разработке», отдельный
     сервис, реализуется позже).
   - **«Запланировать отпуск»** — **текущая реализация целиком**: форма «Новая заявка» +
     календарь пересечений + список «Заявки» с решениями HR. Из формы **убрать селектор
     «Тип»** — планировать можно только **Ежегодный** (тип фиксируется `annual`).
2. Как это оформить в UI: либо две карточки-сервиса на странице, либо переключение
   (вкладки/сегмент) между «Оформить» (заглушка) и «Запланировать». Пользователь выбрал
   подход «текущее в Планировании», «Оформить» — заглушка.

## Срезы (TDD/реализация)

- **T1 — структура страницы**: в VacationsApp сверху/в качестве выбора — два блока/переключатель
  «Оформить отпуск» и «Запланировать отпуск». «Оформить» — заглушка (текст-заглушка, без
  функционала). «Запланировать» — текущее содержимое (форма+календарь+заявки).
- **T2 — убрать «Тип»**: в форме планирования удалить выбор типа, слать `type: 'annual'`
  (только Ежегодный). Бэкенд не меняется (`POST /api/vacations` принимает `type`).
- **T3 — стили/лейаут** под два блока (префиксы сохранить).

## Ограничения

- Не трогать backend/, другие remotes, shell/, tests/ и логику API.
- Тип в существующих заявках остаётся (они могут быть не-annual) — меняется только форма
  планирования.
