# Фича: «Календарь отпусков (отдел)» — 2027

Статус: **реализовано** (слито в master после ревью).

## Что реализовано

1. **Бумажный календарь 2027** в микрофронтенде `vacations` (секция «Календарь отпусков»).
   - 12 месяцев 2027 сеткой 4×3 (Янв-Мар / Апр-Июн / Июл-Сен / Окт-Дек).
   - Каждый месяц — блок с заголовком и сеткой дней Пн-Вс (дни — квадраты/ячейки с числом).
   - Ячейка дня: пустая (рабочий) / **синяя** — в отпуске 1 сотрудник / **красная** — ≥2
     (пересечение); в синей/красной ячейке — инициалы сотрудников.
   - Секция размещена между «Новая заявка» и «Заявки» (читаемость выше — просьба пользователя).
   - Данные: `GET /api/vacations/department` (отпуска отдела по видимости роли). Фильтр по 2027
     выполняется во фронтенде (`buildVacationMap` в `VacationsApp.tsx`), не в SQL бэкенда
     (бэкенд отдаёт все заявки скоупа, но все они 2027 — создание вне 2027 отклоняется 422).
2. **Сворачивание календаря**: по умолчанию видно только 3 первых месяца (Янв-Мар); кнопка
   «Показать все» разворачивает остальные, «Скрыть» — обратно. Кнопка видима и при
   полном раскрытии (иначе нельзя свернуть). Без счётчика месяцев (всего 12 — «(9 мес)» убран).
3. **Строки пересечений под календарём** (блок «Пересечения»): для каждого пересечения —
   «<сотрудник A> ↔ <сотрудник B>: <start> — <end> (<N> дн.)»; пусто → «Пересечений нет».
   Блок тоже сворачивается: по умолчанию 3 строки, кнопка «Показать все» / «Скрыть».
   Источник: `GET /api/vacations/department/overlaps`.

## Правила бэкенда (все — в `backend/`)

- **Только 2027 год.** `POST /api/vacations` возвращает **422**, если `start`/`end` не в 2027
  (страховка поверх UI). SEED — только 2027.
- **Лимит 28 дней/сотрудник/календарный год.** Сумма по всем заявкам сотрудника за 2027;
  превышение → **422**.
- **Самопересечение запрещено; пересечение с коллегой — только предупреждение.**
  `POST /api/vacations` возвращает **422** «Период пересекается с уже существующим отпуском»,
  если новый период пересекается с СОБСТВЕННОЙ заявкой (`status != 'rejected'`). Пересечение
  с отпуском другого сотрудника отдела НЕ блокируется — решает руководитель при согласовании,
  а в форме показывается янтарное предупреждение («В этот период отпуск уже запланирован у …»).
  В UI блок-ошибка появляется сразу при выборе дат (кнопка отправки блокируется).
- **Календарь обновляется динамически.** После создания заявки и после согласования/отклонения
  календарь (`PaperCalendar2027`) перечитывает данные по `refreshKey` — обновления видны
  без перезагрузки страницы (раньше нужен был F5).
- **Дедупликация пересечений.** В `find_overlaps` одинаковые `(employee, start, end)` записи
  учитываются один раз — иначе накопленные дубли дают дублирующиеся строки пересечений.
- `find_overlaps` — чистая функция (stdlib `datetime`), inclusive, не сравнивает отпуска одного
  сотрудника; выдаёт пару с `start=max(...)`, `end=min(...)`, `days=(end-start).days+1`.
- Классификация ячейки дня в UI: синий = 1 сотрудник, красный = ≥2 (пересечение).

## UI-решения

- **Выбор дат в «Новой заявке»** — нативный `<input type="date">` с `min="2027-01-01"`
  `max="2027-12-31"`. Пользователь выбрал именно так («оставим как есть»): нативно скрыть
  другие годы из выпадающего пикера нельзя (мин/макс не ограничивают список годов в Chrome);
  бэкенд всё равно отсекает 422. Альтернатива (два `<select>` месяц+день, фикс. год) была
  отклонена как менее удобная.
- Кастомные селекты были внедрены и **откачены** (`git revert`), вернулись к нативному
  date-input.

## Замечания и вопросы для расширения

- **Демо-данные ресеидаются при рестарте** (`DELETE FROM vacations;` + restart портала → 4
  сид-заявки 2027). Тестовые заявки не удаляются (append-only), чистка — `scripts/cleanup_test_data.sh`.
- **Календарь статичный** (только год 2027, нет месяца назад/вперёд). Расширение: навигация
  по годам, но тогда снять правило «только 2027».
- **28 дней** — жесткий лимит; нет обработки переноса/неиспользованных дней, нет деления по
  типам отпуска (annual/study и т.п.). Расширение: лимиты по типам, перенос остатка, праздничные дни.
- **Начало/конец могут в будущем** — нет проверки «дата не в прошлом». Расширение: запрет
  на прошедшие даты.
- **`structure._current_name()` дублирует логику `auth.current_user()`** (разбор X-User) —
  кандидат на рефакторинг.
- **Правило «только 2027» жёстко захардкожено** в бэке + UI. Расширение: параметризовать год
  (например, из конфигурации), чтобы не менять код ежегодно.
- **Календарь строится для отдела** (плоская модель — один manager_id). Расширение: вложенная
  оргструктура/группы, выбор отдела.
- **Отдельный контейнер на сервис (compose-стек, 7+ контейнеров)** — для демо. Прод-контур (10k
  пользователей): k8s/HPA, Kong, Keycloak, БД-на-сервис, Redis, снятие «только 2027».
