# Сервис «Структура компании» — иерархические отделы/команды

Статус: **реализовано** (as-built, слито в master после ревью).

> История: ниже — исходная постановка (декомпозиция). Пункты реализованы; финальное
> состояние и отличия от постановки — в разделе «As-built» в конце документа.

## Цель

Сейчас «Структура компании» отображает всех сотрудников как единый плоский отдел «HR».
Нужно отразить **иерархические отделы (команды)** по дереву руководителей:
два отдела + топ — как в ролевой модели (см. `docs/auth-service.md`, `docs/role-model-vacation-planning.md`).

## Модель оргструктуры (команды по иерархии)

Дерево подчинённости (по `employees.manager_id`):
```
Иван Петров (top)
└─ Мария Соколова (head)
   ├─ Алексей Ким (head)
   │  └─ Сергей Волков (employee)
   └─ Ольга Романова (employee)
```

Отделы — команды по дереву (у каждого руководителя — своя команда):
- **Отдел Кима** = {Алексей Ким, Сергей Волков}.
- **Отдел Марии** = {Мария Соколова, Алексей Ким, Сергей Волков, Ольга Романова} (включает команду Кима).
- **Топ** (Иван Петров) — видит все отделы.

Видимость структуры: **все видят всю структуру одинаково** (намеренно; см. auth-service.md).

## Данные

- Поле `employees.department` — имя отдела/команды сотрудника (решение: **как поле в БД**):
  - Иван Петров → `HR` (топ).
  - Мария Соколова, Ольга Романова → `отдел Соколовой`.
  - Алексей Ким, Сергей Волков → `Отдел Ким`.
- Источник подчинённости — `manager_id` (не менять).

## Отображение «Структура компании»

- Дерево сотрудников сгруппировано по отделам (**вложенно**): `HR` ⊃ `отдел Соколовой` ⊃ `Отдел Ким`;
  вложенность — по иерархии руководителей (`manager_id`).
- У отдела — название; у сотрудника — имя, должность, руководитель.

## TDD-срезы

- **S0 — данные**: `employees.department` по командам + сид ролей/отделов (Ким/Волков — команда Кима,
  Мария/Ким/Волков/Романова — команда Марии, Иван — топ). RED-тесты.
- **S1 — API структуры**: `/api/structure` отдаёт сотрудников с `department` (команда) — по дереву.
- **S2 — UI**: дерево «Структура компании» группируется по отделам (карточка отдела + руководитель).
- **S3 — тесты**: структура отдаёт отделы/команды корректно; видимость всей структуры для всех ролей.

## Открытые вопросы (решены)

- Названия отделов: `HR` (Иван), `отдел Соколовой` (Мария, Ольга), `Отдел Ким` (Ким, Волков).
- Группировка: **вложенная** (по иерархии руководителей).
- `department` — **поле в БД** (`employees.department`).

## As-built (реализовано)

- Поле `employees.department` заведено и засеяно (Иван → `HR`, Мария/Ольга → `отдел Соколовой`,
  Ким/Волков → `Отдел Ким`); `manager_id` остаётся источником подчинённости.
- `/api/structure` отдаёт всех сотрудников (плоско, с `department` и `manager_id`) — видимость
  всей структуры для всех ролей (намеренно).
- Frontend `services/structure/frontend/src/StructureApp.tsx`:
  - `buildDeptTree()` группирует сотрудников по отделам **вложенно**. Родитель отдела
    определяется по отделу непосредственного руководителя (по иерархии `manager_id`):
    если у всех членов отдела руководители из одного другого отдела — этот отдел является
    родительским; отделы без единственного родителя — корни дерева.
  - Отдел — раскрываемая группа (`st-dept__head` с `aria-expanded`, сворачивание/разворачивание,
    `DeptGroup` самозамкнут через `collapsed`-state). Показывает состав отдела и вложенные
    под-отделы.
  - Ветка `feature/…-frontend` (collapse) слита в master после `feat(structure)` (иерархия).
- Тесты: `services/structure/tests/test_structure.py` (через шлюз).
- Отличие от постановки: в постановке S1/S2 предполагалось «дерево с карточкой отдела +
  руководитель»; в реализации состав отдела показывается списком сотрудников (`st-row`:
  имя + должность), поле «руководитель» в карточке не выводится (определяется по `manager_id`
  из данных структуры).
