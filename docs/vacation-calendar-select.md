# Планирование отпуска — интерактивный выбор периода на календаре

Статус: **реализовано** (as-built, слито в master после ревью).

> Ниже — исходная постановка (декомпозиция). Реализовано: клик-выбор периода на календаре
> с подсветкой, подстановкой в форму и кнопкой «Сбросить». Отличия/нюансы — в разделе
> «As-built и замечания» в конце.

## Цель

В сервисе «Запланировать отпуск» (`services/vacations/frontend`) на календаре (`PaperCalendar2027`)
дать возможность интерактивно выбрать период отпуска кликом по дням: выбранный период
подсвечивается, подставляется в форму (start/end), его можно отправить как заявку.

## Требования

1. **Клик по дню** — начало периода; **второй клик по дню** — конец периода. Период
   `[start, end]` подсвечивается на календаре.
2. **Лимиты**: минимум **1 день**, максимум **28 дней** (полный годовой лимит; далее — блок/подсветка).
3. **Нельзя начинать выбор с выходного** (суббота/воскресенье) — клик по выходному как старт игнорируется.
   Завершить выбор выходным можно (период до него).
4. Выбранный период подставляется в поля формы «Отпуск» (start/end) для отправки заявки.
5. Сброс/новый выбор — третьим кликом или повторным кликом по старту (детали в реализации).

## Место в коде

- `services/vacations/frontend/src/VacationsApp.tsx`:
  - `MonthGridWithTooltip` — отрисовка дней (`<td class="pc-cell">`, `cell.date` ISO, выходные — суб/вс).
  - `PaperCalendar2027` — контейнер календаря, уже перерисовывается по `refreshKey`.
  - `PlanVacations` — экран планирования, форма `start`/`end` (date-input), отправка заявки.
- `services/vacations/frontend/src/styles.css` — классы подсветки выбранного периода.

## Как определить выходной

`new Date(dateStr).getDay()` → 0 (воскресенье) или 6 (суббота). Старт при выходном — запрещён.

## Подсветка

- Дни в выбранном периоде — класс выбора (например `pc-cell--sel`).
- Границы (start/end) — акцент; промежуточные — заливка.
- Пересечение с уже запланированным отпуском — как уже есть (блок своих/предупреждение коллег),
  не ломать существующую логику (`ownOverlap`/`deptOverlap`).

## As-built и замечания (реализовано)

Реализовано в `services/vacations/frontend/src/VacationsApp.tsx` (функция `onSelectDate` +
состояние `selectedStart`/`selectedEnd`, `resetSelection`, кнопка «Сбросить»):

- Клик по дню → старт; второй клик по дню → конец периода. Период `[start,end]` подсвечивается
  (классы `pc-cell--sel`, `--sel-start`, `--sel-end`), границы — акцент.
- Выбранный период сразу подставляется в поля формы `start`/`end` (date-input) и отправляется
  как заявка (`type:'annual'`).
- **Лимиты**: `days < 1` и `days > 28` — сообщение «Период не может быть длиннее 28 дней», выбор
  конца не завершается (подсветка и отправка не происходят).
- **Старт с выходного (сб/вс) запрещён** — клик по выходному как старт игнорируется; завершить
  выбор выходным можно (период до него). Проверка `new Date(date).getDay()` → 0 (вс) / 6 (сб).
- **Сброс/повтор**: клик по тому же дню-старту сбрасывает выбор; клик после завершённого периода
  начинает выбор заново; кнопка «Сбросить» в форме сбрасывает всё.
- Существующая логика `ownOverlap` (блок своих) и `deptOverlap` (предупреждение коллег)
  не изменена и работает поверх выбранного периода (см. `docs/vacation-overlap.md`).

Замечания:
- **Офф-бай-один на календаре в не-UTC таймзоне (MSK/UTC+3)** — `datesInRange()` в
  `buildVacationMap` строит даты через `new Date(iso+'T00:00:00')` и `toISOString().split('T')[0]`,
  а `toISOString` переводит в UTC → для положительного смещения дата сдвигается на день назад
  (отпуск 12–25.01 подсвечивается как 11–24.01). Фикс: формировать `YYYY-MM-DD` из локальных
  компонент (`getFullYear/getMonth/getDate`), не из `toISOString`. Подробно — `docs/tech-debt.md`.
- Бэкенд строго проверяет «только 2027» и лимит (422) — UI-лимиты дублируют серверные
  (в сервере максимум 60 календарных дней, но годовой лимит 28 делает это недостижимым).
- e2e-смоуки выбора периода: `e2e/smoke/test_smoke.py` (тесты #06–#08).
